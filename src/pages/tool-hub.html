03 Why a hub

One place to learn, one set of permissions, one list of problems.

  • AdoptionStaff learn one front door, not five separate tools.
  • GovernancePer-tool access, read-only connections to other systems, and checks that catch a job that quietly stopped.
  • GrowthA new tool registers once and gets sign-in, help and feedback without starting from scratch.
04 How it’s built

One front door, built so every new tool plugs straight in.

  • FrontendReact 18 with Vite, styled with Tailwind and a shared component library, so every tool looks and behaves the same.
  • BackendAn Express API in a monorepo of npm workspaces. Each tool is its own service, deployed to Railway.
  • Sign-inA one-time code is emailed through Microsoft Graph, limited to company addresses. Tool access lists are stored in the database and applied before a tile is even shown.
  • Help and feedbackHelp answers come from a plain-English guide for each tool. Every report lands in one triage database in Notion, and a check fails the build if a new tool isn’t wired in.
  • MonitoringScheduled probes exercise each tool, and a separate check confirms every scheduled job still has a live schedule.
